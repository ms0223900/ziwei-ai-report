# US-003：預覽態解析測試

**作為** 開發者  
**我想要** 先有會失敗的預覽態純函式測試  
**以便** env、query、本地態的組合不會把正式訪客切成已解鎖

**輸入格式**：
- 函式契約（尚未實作），建議 `lib/commercial/preview.ts`（路徑可調，測與實作需一致）
- `isCommercialPreviewEnabled(raw)`：僅 `"1"` 為 true；`undefined`／`""`／`"0"`／其他皆 false
- `resolveEffectivePreviewState({ enabled, localState, searchParams })`：`enabled=false` 一律 `A`；永遠忽略 `preview`／`tier`／`status` query
- `resolvePreviewView({ state, nickname })` 回傳視圖旗標與文案鍵：
  - A：標題「{暱稱}的基本分析」；進階三區鎖定；主 CTA 可見；追問鎖定
  - B：標題「{暱稱}的進階報告」；進階三區顯示「預覽用範例」假文；主 CTA 隱藏或已解鎖；追問仍鎖定
  - C：同 B；追問外觀解鎖；標「預覽：尚未扣點」
  - D：同 C；標「本月剩餘 10 次（預覽）」；訂閱入口「訂閱有效（預覽）」
- 假文必須含「預覽用範例」，禁止把 `advanced_json` 真文當輸入

**輸出格式**：
- 對應 `*.test.ts`（與實作檔同目錄）

**驗收條件**：
- [ ] 聚焦測試因功能尚未實作而預期紅燈
- [ ] 斷言 env 只有 `"1"` 開啟；query 無法把有效態改成 B／C／D
- [ ] 斷言 A／B／C／D 的標題、鎖定、CTA、追問、訂閱旗標
- [ ] 斷言範例文案含「預覽用範例」，輸入物件即使帶 `rationale` 也不被採用

**測試策略**：Test-First（測試準備）
> 理由：env／query／四態是明確的狀態轉換，適合先紅後綠。
