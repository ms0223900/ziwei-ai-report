# US-023：測試帳號與交棒

**作為** 講師／學員  
**我想要** 兩個固定測試帳號與欄位交棒清單  
**以便** 單元 7／8 能讀同一套資料驗重送與不足

**輸入格式**：
- spec Story 13：帳號 A `points_balance=5`、目標報告 `user_id=A` 且無該列 `report_unlocks`；帳號 B 餘額 0
- 單元 7 只讀：`orders.plan_id/status/amount/merchant_trade_no`、`points_balance`、帳本列、`report_unlocks`
- 單元 8 用本版資料驗重送、扣點成功、不足；本單不寫完整驗測劇本
- 課堂規則：訪客報告須登入後**新產生**；grant ≠ 加點 ≠ 任意 uuid 通行證；點數包驗收禁用 grant
- US-022 回跳文案已中性

**輸出格式**：
- howto（建議 `docs/user-stories/ziwei-unit5-points-pack-unlock/howto-points-pack.md`）
- 可附 seed／Checkpoint 說明；不必每次現場付款
- 本任務不改產品行為

**驗收條件**：
- [ ] 文件能依帳號 A 走 Story 8 Happy（有餘額、自己的報告）
- [ ] 文件能依帳號 B 走 Story 11 不足阻擋
- [ ] 列出單元 7／8 可讀的訂單、餘額、帳本、選單四類欄位
- [ ] 寫明 grant 不算加點、進階仍要 `reports.user_id`；權益鍵是 `persist_id`
- [ ] 寫明不可再用「再送同一生辰」當終身／單點進階捷徑；單元 4 SOP 同句在本單元作廢

**測試策略**：Exploratory  
> 理由：交棒與課堂資料是文件產出，無產品邏輯可先紅。

**優先級**：P0  
**相關功能**：Story 13；spec 第 7 節問題 5
