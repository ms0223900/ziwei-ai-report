# US-006：點數包建單與閘門 測試

**作為** 開發者  
**我想要** 先有會失敗的點數包建單測試  
**以便** 已開通仍可買點，終身方案仍 409

**輸入格式**：
- `POST /api/payments/checkout`；JSON `{ "plan_id": "points_pack_5" }`
- 忽略 body 的 `amount`／`points`／`ItemName`
- 未登入：401「請先登入。」不寫單
- 未知 plan：400「不支援的方案。」
- `locked` 會員：200、pending、`amount=49`、`TotalAmount=49`、`ItemName=紫微斗數點數包（5 點）`
- `unlocked` + `points_pack_5`：200、新建 pending（**禁止** 409）
- `unlocked` + `unlock_report_lifetime`：仍 409「此帳號已開通，無需再次付款。」
- 資料層用 US-005 fake

**輸出格式**：
- 對應 `*.test.ts`（建議擴充 `app/api/payments/checkout/route.test.ts`）

**驗收條件**：
- [ ] 聚焦測試因功能尚未實作而預期紅燈
- [ ] 斷言 `points_pack_5` 以 49 建單；body 帶 `amount: 1` 仍 49
- [ ] 斷言已開通買點數包 200、不 409
- [ ] 斷言已開通買終身仍 409、不寫新單
- [ ] 斷言 401／400 繁中且不寫 pending

**測試策略**：Test-First（測試準備）  
> 理由：閘門依 `plan_id` 的 HTTP 契約明確，適合先紅後綠。
