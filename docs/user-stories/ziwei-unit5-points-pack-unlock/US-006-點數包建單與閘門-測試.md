# US-006：點數包建單與閘門 測試

**作為** 開發者  
**我想要** 先有會失敗的點數包建單測試  
**以便** 已開通仍可買點，終身方案仍 409

**輸入格式**：
- `POST /api/payments/checkout`；JSON `{ "plan_id": "points_pack_5" }`
- 忽略 body 的 `amount`／`points`／`ItemName`
- 未登入：401「請先登入。」不寫單
- 未知 plan：400「不支援的方案。」
- `locked` 會員：200、pending、`amount=49`、`TotalAmount=49`、`ItemName=紫微斗數點數包（5 點）`
- `unlocked` + `points_pack_5`：200、新建 pending（**禁止** 409）
- `unlocked` + `unlock_report_lifetime`：仍 409「此帳號已開通，無需再次付款。」
- 資料層用 US-005 fake

**輸出格式**：
- 對應 `*.test.ts`（建議擴充 `app/api/payments/checkout/route.test.ts`）

**驗收條件**：
- [x] 聚焦測試因功能尚未實作而預期紅燈
- [x] 斷言 `points_pack_5` 以 49 建單；body 帶 `amount: 1` 仍 49
- [x] 斷言已開通買點數包 200、不 409
- [x] 斷言已開通買終身仍 409、不寫新單
- [x] 斷言 401／400 繁中且不寫 pending

#### 驗收說明

**整體結論**：PREPARED：預期紅燈測試已建立

> `npx vitest run app/api/payments/checkout/route.test.ts`：9 tests，1 failed／8 passed。待 US-007 轉綠。

路徑：`app/api/payments/checkout/route.test.ts`  
原因：`unlocked` 會員送 `points_pack_5` 仍走既有閘門，回 409「此帳號已開通，無需再次付款。」且不寫 pending。失敗訊息是 `expected 409 to be 200`，不是測試語法或 import 錯誤。`locked` 會員的 49 建單（忽略 body `amount: 1`）與既有 401／400／終身 409 案例已綠。
