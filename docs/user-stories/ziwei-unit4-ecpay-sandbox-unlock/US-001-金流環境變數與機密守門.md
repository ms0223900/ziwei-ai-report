# US-001：金流環境變數與機密守門

**作為** 開發者  
**我想要** ECPay URL／Hash 槽位與機密守門齊全  
**以便** 建單與 Webhook 能讀 server env，且 Hash 不進 client

**輸入格式**：
- spec §4 變數：`ECPAY_MERCHANT_ID`、`ECPAY_HASH_KEY`、`ECPAY_HASH_IV`、`ECPAY_CHECKOUT_URL`、`ECPAY_QUERY_URL`、`ECPAY_RETURN_URL`、`ECPAY_CLIENT_BACK_URL`、`ECPAY_ENV`、`APP_BASE_URL`
- Stage checkout 預設值可寫在 `.env.example` 註解或預設 URL；Hash 槽位必須空字串
- 既有 `lib/security/secrets-not-leaked.test.ts` 的 `SECRET_ENV_KEYS`

**輸出格式**：
- `.env.example` 補齊上述鍵（無真實 Hash）
- 守門測試持續禁止 `NEXT_PUBLIC_ECPAY_HASH_*`／Hash 字串進 client

**驗收條件**：
- [ ] `.env.example` 有 spec 列的 ECPay URL 與 Hash 空槽
- [ ] 無任何 `NEXT_PUBLIC_*` 帶 HashKey／HashIV／service role
- [ ] 不把公開測試特店帳密寫成程式常數
- [ ] `ECPAY_QUERY_URL` 只留槽位；本任務不呼叫 QueryTradeInfo
- [ ] `.env.example` 綠界註解不再寫「本版不使用」

**測試策略**：Test-After  
> 理由：改 env 範例與既有守門名單，補跑現有測試即可。
