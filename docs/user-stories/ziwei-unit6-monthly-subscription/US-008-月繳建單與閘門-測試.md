# US-008：月繳建單與閘門 測試

**作為** 開發者  
**我想要** 先有會失敗的月繳建單與閘門測試  
**以便** 定期定額參數與防重複建單規則被鎖住

**輸入格式**：
- `app/api/payments/checkout/route.ts`、`route.test.ts`
- spec §2 Story 1／2；AC S1-1～S2-4

**輸出格式**：
- 擴充 `app/api/payments/checkout/route.test.ts`

**驗收條件**：
- [ ] 聚焦測試因功能尚未實作而預期紅燈（失敗原因是功能缺失，不是語法／import 錯誤）
- [ ] S1-1：`fields` 含 `TotalAmount=19`、`PeriodAmount=19`、`PeriodType=M`、`Frequency=1`、`ExecTimes=12`、`PeriodReturnURL`、`ChoosePayment=Credit`，且 `CheckMacValue` 可驗；`orders` 新增 pending／19
- [ ] S1-2 前端夾帶的金額／週期被忽略；S1-3 未登入 401；S1-4 已永久解鎖仍 200
- [ ] S1-5 缺 `PeriodReturnURL` 時月繳回 `PAYMENT_UNAVAILABLE`，點數包仍 200
- [ ] S2-1 期末未過（`active` 或 `past_due`）回 409 繁中訊息；S2-2 5 分鐘內有 pending 月繳訂單回 409，超過 5 分鐘回 200；S2-3 已取消或到期回 200；S2-4 未知 plan 回 400

**測試策略**：Test-First  
> 理由：API 輸入輸出與閘門條件明確。

**優先級**：P0
