**作為** 開發者  
**我想要** 先有會失敗的月繳建單與閘門測試  
**以便** 定期定額參數與防重複建單規則被鎖住

**輸入格式**：
- `app/api/payments/checkout/route.ts`、`route.test.ts`（已有 `setPaymentEnv`）
- spec §2 Story 1／2；AC S1-1～S2-4

**輸出格式**：
- 擴充 `app/api/payments/checkout/route.test.ts`

**驗收條件**：
- [ ] 聚焦測試因功能尚未實作而預期紅燈（失敗原因是功能缺失，不是語法或 import 錯誤）
- [ ] S1-1：`fields` 含 `TotalAmount=19`、`PeriodAmount=19`、`PeriodType=M`、`Frequency=1`、`ExecTimes=12`、`PeriodReturnURL`、`ChoosePayment=Credit`，且 `CheckMacValue` 可驗；`orders` 新增一筆 pending、金額 19
- [ ] S1-2：前端夾帶的金額或週期被忽略；S1-3：未登入回 401，`orders` 沒有新增；S1-4：已永久解鎖仍回 200
- [ ] S1-5：保留 `ECPAY_RETURN_URL`／`ECPAY_CLIENT_BACK_URL`、清掉 `APP_BASE_URL` 與 `ECPAY_PERIOD_RETURN_URL` 時，月繳回 `PAYMENT_UNAVAILABLE` 且 `orders` 沒有新增；點數包仍回 200
- [ ] S2-1：期末未過（`active` 或 `past_due`）時回 409 並帶繁中訊息，`orders` 沒有新增
- [ ] S2-2：5 分鐘內有 pending 月繳單時回 409；用假時鐘推進超過 5 分鐘後回 200；5 分鐘內只有 pending **點數包**單時不擋月繳
- [ ] S2-3：已取消或已到期時回 200；S2-4：未知 plan 回 400 `UNSUPPORTED_PLAN`
- [ ] 備註：S1-4／S2-4 等可能在 US-002 完成後就已經是綠的，只有新行為的斷言需要先紅

**測試策略**：Test-First（測試準備）
