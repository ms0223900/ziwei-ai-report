**作為** 開發者  
**我想要** 先有會失敗的月繳方案與 PeriodReturnURL 設定測試  
**以便** 金額、週期、品名只由後端決定

**輸入格式**：
- `lib/payments/plans.ts`：目前只有終身與點數包兩個方案
- `lib/payments/checkout-env.ts`：沒有 `periodReturnUrl`
- 定稿值：`subscribe_report_monthly`、19／TWD／「紫微斗數月繳訂閱」、`M`／`1`／`12`

**輸出格式**：
- 擴充 `lib/payments/plans.test.ts`
- 新增或擴充 checkout-env 測試

**驗收條件**：
- [ ] 聚焦測試因功能尚未實作而預期紅燈（失敗原因是功能缺失，不是語法或 import 錯誤）
- [ ] 斷言 `resolveCheckoutPlan("subscribe_report_monthly")` 回傳 19／TWD／品名，且 `period` 為 `{periodType:"M", frequency:1, execTimes:12}`
- [ ] 斷言終身 99、點數包 49 不變；未知 plan 回 `null`
- [ ] 斷言 `ECPAY_PERIOD_RETURN_URL` 優先；未設時用 `APP_BASE_URL + /api/payments/ecpay/period-webhook`
- [ ] 斷言只設 `ECPAY_RETURN_URL` 與 `ECPAY_CLIENT_BACK_URL`、不設 `APP_BASE_URL` 時：`readEcpayCheckoutEnv()` 不回 null，`periodReturnUrl` 為空字串

**測試策略**：Test-First（測試準備）
