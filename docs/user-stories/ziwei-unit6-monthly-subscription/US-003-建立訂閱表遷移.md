# US-003：建立訂閱表遷移

**作為** 系統  
**我想要** 建立 `subscriptions`、`subscription_events` 兩張表並設定 RLS  
**以便** 訂閱狀態與事件有持久來源，且只能由後端寫入

**輸入格式**：
- spec §4 DB Schema
- RLS 與 revoke 比照 `supabase/migrations/20260918000000_create_orders.sql`

**輸出格式**：
- `supabase/migrations/20260925000000_subscriptions.sql`
- `supabase/migrations/subscriptions.migration.test.ts`（比照既有 `*.migration.test.ts`，檢查 SQL 內容）

**驗收條件**：
- [x] `subscriptions` 欄位：`plan_id text not null`、`order_id references orders(id)`、`user_id` 為 unique 並 `on delete cascade`、`merchant_trade_no not null unique`；`status` 的 check 只允許 `active|past_due|cancelled|expired`；起訖時間 `not null`；有 updated_at trigger
- [x] `subscription_events` 欄位：`subscription_id` 與 `user_id` 皆 `on delete cascade`；`idempotency_key not null unique`；`event_type` 的 check 允許 `first_success|first_duplicate|renewal_success|payment_failed|cancelled|expired`；另有 `gwsr`、`total_success_times`、`rtn_code`；`processed_at not null`
- [x] 兩張表都啟用 RLS：authenticated 只能 select 自己的列；anon／authenticated 不能 insert／update／delete
- [x] 不改 `orders`、`profiles` 的結構
- [x] migration 測試通過
- [⚠️] 已套用至 Supabase。套用後以 authenticated 身分實測 S11-1：對兩張表 insert／update 都被拒，並把結果貼進驗收說明

#### 驗收說明

**整體結論**：PARTIAL ⚠️

> 遷移與內容測試都已完成；在 PGlite 上依序套用全部 migration 成功，並模擬了 S11-1。唯一缺口是 Supabase 實際套用與實測，依使用者決定留待人工回報。

**AC-1：`subscriptions` 欄位、unique、status check、起訖 not null、updated_at trigger**

狀態：✅ 通過

- `supabase/migrations/20260925000000_subscriptions.sql`：`user_id` 為 unique 且 `on delete cascade`；`merchant_trade_no` 為 `not null unique`；status 只允許四值（不含 pending）；有 `subscriptions_set_updated_at` trigger
- `subscriptions.migration.test.ts` 的前 3 支案例鎖定上述行為

---

**AC-2：`subscription_events` 欄位、cascade、unique 冪等鍵、6 種 event_type**

狀態：✅ 通過

- 同一檔的 `subscription_events`：兩個 FK 都 `on delete cascade`；`idempotency_key` 為 unique；check 涵蓋 6 種 event_type；另有 `gwsr`／`total_success_times`／`rtn_code`；`processed_at` 為 not null

---

**AC-3：兩表 RLS，只能讀自己的，client 不可寫**

狀態：✅ 通過

- `*_select_own` policy 以 `auth.uid() = user_id` 限定；對 anon revoke all，對 authenticated revoke insert／update／delete（`it.each` 兩表都驗）

狀態：✅ 通過
