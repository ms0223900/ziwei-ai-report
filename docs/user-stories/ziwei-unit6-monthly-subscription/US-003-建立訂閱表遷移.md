# US-003：建立訂閱表遷移

**作為** 系統  
**我想要** 有 `subscriptions`、`subscription_events` 兩張表，並設好 RLS  
**以便** 訂閱狀態與事件有持久、只能由後端寫入的來源

**輸入格式**：
- spec §4 DB Schema
- 比照 `supabase/migrations/20260918000000_create_orders.sql` 的 RLS／revoke 寫法

**輸出格式**：
- `supabase/migrations/20260925000000_subscriptions.sql`
- `supabase/migrations/subscriptions.migration.test.ts`（比照既有 `*.migration.test.ts` 檢查 SQL 內容）

**驗收條件**：
- [ ] `subscriptions`：`user_id` unique + `on delete cascade`；`merchant_trade_no not null unique`；`status` check 只含 `active|past_due|cancelled|expired`；起訖 `not null`；有 updated_at trigger
- [ ] `subscription_events`：`subscription_id` 與 `user_id` 皆 `on delete cascade`；`idempotency_key not null unique`；`event_type` check 含 `first_success|first_duplicate|renewal_success|payment_failed|cancelled|expired`；`processed_at not null`
- [ ] 兩表 RLS：authenticated 只能 select 自己的列；anon／authenticated 無 insert／update／delete
- [ ] 不改 `orders`、`profiles` 結構
- [ ] migration 測試通過；已在 Supabase 套用並回報結果（未套用前不得勾 US-011／US-013 的 DB 相關 AC）

**測試策略**：Test-After  
> 理由：驗收靠遷移內容與套用結果，不適合先寫單元測試。

**優先級**：P0  
**相關功能**：Story 11；spec §4  
**依賴關係**：無
