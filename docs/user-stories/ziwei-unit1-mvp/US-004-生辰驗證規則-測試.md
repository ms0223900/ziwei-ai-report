# US-004：生辰驗證規則測試

**作為** 開發者  
**我想要** 先有會失敗的生辰驗證測試  
**以便** 實作時有明確紅燈可轉綠

**輸入格式**：
- 函式契約（尚未實作）：`lib/validation/birth.ts`
- 合法：`nickname` trim 後長度 ≥ 1；`birth_date` = `YYYY-MM-DD` 且非未來（日曆日 `Asia/Taipei`）；`birth_time` = `null` 或 12 支；`focus` = `整體`／`工作`／`關係` 或空
- 示範：暱稱「小圓」、`1993-07-12`、`birth_time=null`、`focus=工作`
- 專案尚無測試 runner → 本任務一併加入 Vitest（co-locate `*.test.ts`）。後續所有 Test-First 測試任務依賴本 runner，不得另開第二套。

**輸出格式**：
- `lib/validation/birth.test.ts`（或專案慣例檔名）
- `package.json` 可跑的 `test` script（若原本沒有）

**驗收條件**：
- [ ] 聚焦測試因功能尚未實作而預期紅燈
- [ ] 涵蓋：合法示範、空白暱稱、空白／非法／未來生日、非法時辰（含字串「不確定」與 `14:00`）、非法 focus「感情」、空 focus 視為 `整體`
- [ ] 合法案例斷言輸出含 `time_unknown=true` 且請求層 `birth_time` 為 `null`
- [ ] 未實作時測試失敗原因是「找不到模組／函式行為不符」，不是測試寫錯、也不是沒有 `npm test`

**測試策略**：Test-First（測試準備）
> 理由：驗證規則是明確 input／output，先紅後綠。
