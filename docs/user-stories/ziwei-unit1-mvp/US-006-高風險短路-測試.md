# US-006：高風險短路測試

**作為** 開發者  
**我想要** 先有會失敗的高風險掃描測試  
**以便** 實作時鎖住五類固定回覆

**輸入格式**：
- 函式契約（尚未實作）：`lib/policy/high-risk.ts`
- 掃描所有字串欄（至少 `nickname`，`focus` 一併掃）
- 五類：`health`／`legal`／`financial_risk`／`pregnancy`／`self_harm`
- 例句：暱稱「這筆投資會不會賺」→ `financial_risk`；一般「小圓」→ 未命中
- 多類命中：第一個命中類

**輸出格式**：
- `lib/policy/high-risk.test.ts`
- 斷言命中時的 `category` 與固定繁中 `message`

**驗收條件**：
- [ ] 聚焦測試因功能尚未實作而預期紅燈（以 US-004 的 `npm test` 跑；紅燈不得是沒有測試指令）
- [ ] 涵蓋五類各至少 1 個明確詞、未命中「小圓」、多類取第一個
- [ ] 詞表不斷言單字「金」為命中（避免誤殺）
- [ ] 固定文案與 AI spec Story 4／design brief 一致

**測試策略**：Test-First（測試準備）
> 理由：關鍵字 → category／文案是明確 I/O。
