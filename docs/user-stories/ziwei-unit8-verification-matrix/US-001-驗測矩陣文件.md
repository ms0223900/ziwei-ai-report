# US-001：驗測矩陣文件

**作為** 學員  
**我想要** 一張含三種模式所有 Must 列的共用矩陣  
**以便** 逐列勾選通過／未通過並指出證據位置

**輸入格式**：
- spec §2 帳號分配、FR-1 欄位與預填表、頁首三條執行規則
- Notion §7.1／§7.2

**輸出格式**：
- `docs/unit8/verification-matrix.md`

**驗收條件**：
- [x] 欄位依序為：案例 ID、模式、案例、測試帳號、重播方式、訂單或事件識別、預期權益、結果頁、通知、管理紀錄、實際結果／證據位置、通過／未通過、處置
- [x] 含 13 個 Must ID：U8-L-S、U8-L-F、U8-L-D、U8-P-S、U8-P-F、U8-P-D、U8-S-S、U8-S-F1、U8-S-F2、U8-S-F3、U8-S-F4、U8-S-D、U8-N-F
- [x] 每列前 10 欄（案例 ID～管理紀錄）非空；不適用的格子寫「不適用：<理由>」，全文沒有 `—`
- [x] 「實際結果／證據位置」預填 SQL 檔名、`probe.mjs` 指令或「Checkpoint：<檔名>」
- [x] 「通過／未通過」為可勾選空格
- [x] 頁首註明處置欄「通過則空、未通過連到處置卡」
- [x] 「預期權益／結果頁／通知／管理紀錄」只寫可查值：欄位值、screen 值＋標題、type／idempotency_key、原因字串或事件 key；不出現「正常」「成功即可」
- [x] U8-L-F、U8-P-F、U8-S-F1 的結果頁欄寫出使用者下一步（CTA 或提示），管理紀錄欄寫出管理者原因或事件；U8-P-F 以 R 的帳本 SQL 為管理者證據
- [x] U8-S-D 的預期權益依 spec 表格區分 return 重送與 `--total-success-times 1` 的事件筆數
- [x] 頁首有三條執行規則：等待超過 3 分鐘切 Checkpoint；回跳參數不算證據；手動 UPDATE 權益不算通過
- [x] 頁首有帳號分配（A／B／C／D 各負責的列、A 先 F3 後 reset 再 F2 取消、點數模式順序 U8-P-F → U8-P-S／D → U8-N-F）


#### 驗收說明

**整體結論**：PASS ✅

> `docs/unit8/verification-matrix.md` 已建立，含 13 個 Must 列，分成單次解鎖、點數、訂閱、共用四張表。以 awk 檢查每列前 10 欄皆非空，並以 grep 確認全文沒有 `—`、「正常」、「成功即可」。
