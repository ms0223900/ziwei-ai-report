# US-015：單點解鎖通知 測試

**作為** 開發者  
**我想要** 先有會失敗的單點解鎖通知測試  
**以便** 只有真正扣點解鎖時才通知

**輸入格式**：
- spec §2 Story 5（`report_unlocked` 列）
- `app/api/reports/unlock-with-point/route.ts`；RPC 只回 `ok, reason, points_balance`，不回 transaction id

**輸出格式**：
- `app/api/reports/unlock-with-point/route.test.ts` 新增案例

**驗收條件**：
- [ ] 聚焦測試因功能尚未實作而預期紅燈（失敗原因是功能缺失，不是語法或 import 錯誤）
- [ ] S5-3：RPC 回 `reason=unlocked` → 恰一則 `report_unlocked`，key 為 `debit:{point_transactions.id}`，`source_type=report`
- [ ] transaction id 取自 `point_transactions` 中 `user_id`＋`report_id`＋`type=debit_unlock` 的那一列
- [ ] S5-3：`reason` 為 `already_unlocked`、`insufficient`、`forbidden`、`lifetime`、`subscription` → 通知數不變
- [ ] 通知 insert 失敗 → 回應與既有成功回應相同

**測試策略**：Test-First 測試準備  
> 理由：分支條件明確。
