# 單元 8 上線前處置卡

> 規格：[`docs/specs/2026-10-05-ziwei-unit8-verification-matrix.md`](../specs/2026-10-05-ziwei-unit8-verification-matrix.md) §2 FR-7  
> 矩陣：[`verification-matrix.md`](./verification-matrix.md)：未通過的列在「處置」欄連到這裡的卡。  
> 交棒：填好的 1～3 張卡交給單元 9 展示與取捨。

## 規則

- **排序**：8-2 驗出下列任一種阻斷型問題時，該卡排在預填卡之前：
  1. 錯誤解鎖
  2. 重複加點
  3. 過期仍可用
  4. 已收款未交付
  5. 交易無法追查

  其餘依矩陣列的風險排序：錯誤交付 → 已收款未交付 → 過期權益 → 交易無法追查 → 已履約無通知。
- **處置完成的定義**：缺「重新驗測條件」，或該欄不是可勾選清單的卡，視為未完成處置。
- **改不改程式**：課內不修產品程式，只填卡。要為補通知、補期新增產品 API，須先問（Notion §13 Ask first）。
- **預填範例**：下方 3 張預填卡是已知的產品限制，屬於教材範例。課堂若驗出更高風險的問題，可以替換掉。

## 預填卡

### 卡 1：PeriodReturnURL 每期只通知一次，漏收沒有補單機制

| 欄位 | 內容 |
| --- | --- |
| 問題 | 綠界每期只送一次 PeriodReturnURL；本地漏收該期事件時，沒有補單或補事件的機制 |
| 影響範圍 | 訂閱制會員；綠界已扣款，但本地期末沒延展，使用者付了錢卻失去進階內容 |
| 交易證據 | 該訂閱的 MTN；`subscription_events` 缺少 `period:{mtn}:{n}`；綠界後台的該期扣款紀錄；矩陣 U8-S-S／U8-S-D |
| 優先級 | 人工接手 |
| 暫時措施 | 對外不承諾「沒收到通知也會自動補期」；管理者用綠界後台對帳後，再走受控流程（retry 屬 Could，本版不新做） |
| 處理人 | 講師 |
| 重新驗測條件 | 見下方清單 |
| 上線狀態 | 修正後開放（自動續期的承諾）；在此之前標為已知限制 |

重新驗測條件：

- [ ] 模擬漏收一期時，權益依期末正確失效，且能從 `subscription_events` 與綠界後台追查到缺的那一期
- [ ] 補單或補事件機制完成後，重播該期成功通知只延展一次（同一 `period:{mtn}:{n}` 只有 1 筆）

### 卡 2：產品內取消不會停止綠界合約

| 欄位 | 內容 |
| --- | --- |
| 問題 | 在產品內取消訂閱只收回本地權益，不會停止綠界的定期定額合約 |
| 影響範圍 | 訂閱制會員；取消後綠界仍可能扣下一期，本地不會恢復權益，但顧客可能被重複扣款 |
| 交易證據 | `cancel:{subscription_id}:{mtn}` 事件；取消後若收到下一期成功通知，會留下 `period:{mtn}:{n}`，但期末不延長；矩陣 U8-S-F2 |
| 優先級 | 人工接手 |
| 暫時措施 | 在教材與對顧客的說明中講清楚：取消權益不等於停掉綠界定期扣款，需另外在綠界或卡片端處理。產品已驗證「取消後成功通知不會恢復權益」 |
| 處理人 | 講師 |
| 重新驗測條件 | 見下方清單 |
| 上線狀態 | 可繼續測試；正式對外前必須有停約說明或流程 |

重新驗測條件：

- [ ] 取消後再送下一期成功通知：回 `1|OK`，只記錄事件，期末不延長
- [ ] 實際停約步驟（綠界後台或 API）完成並寫進說明後，才關閉此缺口

### 卡 3：已有有效訂閱又收到第二筆付款時，不建立第二份訂閱

| 欄位 | 內容 |
| --- | --- |
| 問題 | 已有有效訂閱時，再建月繳單會回 409；若 webhook 仍送來第二筆付款，只記 log，不建立第二份訂閱 |
| 影響範圍 | 訂閱制會員；使用者可能以為買了第二份，金流已收款但本地不增加權益，造成對帳負擔 |
| 交易證據 | 建單 API 的 409 回應；第二筆付款的 MTN 與 webhook log；`subscriptions` 仍只有 1 列 |
| 優先級 | 可延後 |
| 暫時措施 | 前端維持 409「已有有效訂閱或訂單處理中」；管理者對帳時以事件 log 為準，不手動改成第二份訂閱 |
| 處理人 | 講師 |
| 重新驗測條件 | 見下方清單 |
| 上線狀態 | 可繼續測試；標為已知的對帳限制 |

重新驗測條件：

- [ ] 有效訂閱期間再按月繳 CTA，仍回 409
- [ ] 重放第二筆付款通知：不新增訂閱、不延長期末、不新增 `subscription_active` 通知

## 人工接手範圍

| 允許 | 禁止 |
| --- | --- |
| 查詢訂單、帳本、事件、通知 | 把未驗簽、未付款或已 failed 的訂單改成 paid |
| 在處置卡或對帳表註記 | 直接改 `points_balance` |
| 暫停購買入口 | 手改訂閱期末（`current_period_end`） |
| 使用既有的管理者補點 API（`/admin/orders` 的補 5 點，`admin_actions.action=credit_points`） | 手動補建成功通知來讓矩陣通過 |
